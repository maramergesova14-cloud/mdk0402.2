# МДК.04.02 — Проектирование программного обеспечения

## Тема: «Электронный журнал группы»

**Тип работы:** проектирование информационной системы учёта успеваемости и посещаемости.  
**Формат:** веб-приложение с серверной частью и базой данных.  
**Связанный программный проект:** https://github.com/maramergesova14-cloud/elektronnyi-zhurnal

> Этот репозиторий описывает целевое проектное решение. Наличие функции в документации не означает, что она уже реализована в текущем коде. Авторизация с ролями, расчёт среднего балла и расширенная отчётность требуют отдельной реализации и проверки.

## 1. Постановка задачи

Сведения об оценках и посещаемости могут храниться в разных таблицах или бумажных журналах. Это усложняет поиск информации, повышает риск ошибок и увеличивает время подготовки итоговых сведений.

Цель проектирования — определить структуру веб-системы, которая централизованно хранит сведения о студентах, предметах, оценках и посещаемости.

## 2. Предполагаемые функции

- ведение справочника студентов;
- ведение справочника предметов;
- создание и просмотр оценок;
- учёт посещаемости;
- просмотр сведений по студенту и предмету;
- административное управление справочниками;
- в целевой версии — авторизация и разграничение прав;
- в целевой версии — расчёт среднего балла и формирование отчётов.

## 3. Выбор технологий

- **Python** — язык серверной логики;
- **Django** — веб-фреймворк;
- **Django REST Framework** — создание API;
- **SQLite** — база данных для локальной разработки;
- **PostgreSQL** — вариант базы данных для развёртывания;
- **Git и GitHub** — хранение кода и документации.

Фактическая СУБД определяется настройками окружения. Для использования PostgreSQL требуется корректно настроить параметры подключения.

## 4. Основные сущности

| Сущность | Назначение |
|---|---|
| Student | Студент и сведения о группе |
| Subject | Учебный предмет |
| Grade | Оценка студента по предмету |
| Attendance | Посещаемость студента на занятии |

Поля и связи описаны в [BAZA_DANNYH.md](BAZA_DANNYH.md).

Возможные доработки: роли «Администратор», «Преподаватель», «Студент»; ограничения доступа; автоматический расчёт среднего балла; отчёты по студентам, предметам и периоду; журналирование важных действий. Перед сдачей нужно сопоставить эти пункты с кодом и результатами тестов.
