# План тестирования системы «Электронный журнал»

## 1. Цель

Проверить, что основные операции с учебными данными работают корректно, связи между сущностями сохраняются, а некорректные запросы обрабатываются предсказуемо.

## 2. Подготовка

- использовать тестовую базу данных и синтетические данные;
- подготовить минимум одного студента и один предмет;
- записывать входные данные и фактический ответ;
- не выполнять разрушительные проверки на базе с важными данными;
- после теста удаления проверить результат отдельным запросом.

## 3. Тестовые сценарии

| ID | Сценарий | Ожидаемый результат |
|---|---|---|
| TC-01 | Получить список студентов | API возвращает список |
| TC-02 | Создать студента с корректными полями | Запись создана |
| TC-03 | Изменить поле студента | Новое значение сохранено |
| TC-04 | Запросить несуществующий идентификатор | API возвращает соответствующую ошибку |
| TC-05 | Получить список предметов | Возвращаются предметы |
| TC-06 | Создать оценку для существующего студента и предмета | Оценка сохранена с правильными связями |
| TC-07 | Создать оценку с несуществующей связью | Запрос отклонён проверкой |
| TC-08 | Создать запись посещаемости | Запись сохраняется с датой и статусом |
| TC-09 | Передать неизвестный статус посещаемости | Значение отклоняется, если набор статусов ограничен моделью |
| TC-10 | Изменить и удалить тестовую запись | Операция соответствует поведению API |
| TC-11 | Открыть административную панель | Доступный администратор может управлять зарегистрированными моделями |
| TC-12 | Перезапустить приложение и повторить GET | Данные сохранены в базе |
| TC-13 | Проверить права ролей (целевая функция) | Каждая роль может выполнять только разрешённые действия |
| TC-14 | Проверить средний балл (целевая функция) | Результат совпадает с контрольным расчётом |
| TC-15 | Проверить отчёт за период (целевая функция) | В отчёте присутствуют записи заданного периода |

## 4. Форма протокола

Для каждого сценария следует заполнить:

| Поле | Что записывать |
|---|---|
| ID теста | Например, TC-01 |
| Дата и версия | Когда и на какой версии выполнена проверка |
| Предусловия | Какие данные подготовлены |
| Действия | Последовательность шагов |
| Ожидаемый результат | Что должно произойти |
| Фактический результат | Что произошло при запуске |
| Статус | Пройден / Не пройден / Не выполнялся |
| Примечания | Ошибки и ссылки на исправления |

Таблица сценариев является планом. Не отмечайте тест пройденным без фактической проверки.

## 5. Критерии приёмки

- основные операции CRUD проверены для поддерживаемых ресурсов;
- оценки и посещаемость связаны с корректными студентами и предметами;
- ошибки валидации обрабатываются ожидаемым образом;
- приложение и база данных запускаются по инструкции;
- критические дефекты устранены;
- для каждой дополнительной функции есть отдельный тест;
- ограничения текущей версии перечислены в документации.

## 6. Запуск автоматических тестов Django

Из каталога, где находится `manage.py`, выполнить:

```bash
python manage.py test
```

Если тесты не созданы или команда завершилась ошибкой, результат нужно зафиксировать и исправить проблему. Нельзя сообщать об успешном прохождении тестов без фактического запуска.
